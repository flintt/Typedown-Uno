# 与 Windows 原生版的功能差距

对照日期 2026-09-24，Windows 侧为 `flintt/Typedown` v1.2.25，Uno 侧为 v1.1.2 之后的主线。
这份清单只列**用户可见的功能**；架构差异（Core 复用、协议、存储格式）不在其中。

## 已对齐

文件、编辑、段落、格式、视图五个菜单的主干；标签页（Alt+1~9 按位置、Alt+0 上次使用、滚轮切换、
拖拽顺序除外）；侧边栏文件树与大纲、文件夹搜索、文件树跟随当前文档；会话恢复；自动保存与外部变更
重载；自定义主题与六个内置主题；编辑器设置（字号、行高、编辑区宽度、字体、缩进、表格对齐、段落标记、
拼写检查、自动配对、自定义 CSS）；图片设置；查找选项；快捷键设置；HedgeDoc 分享；状态栏与字数统计；
十种界面语言。

## 差距一：导出与打印

| | Windows | Uno |
|---|---|---|
| 导出格式 | HTML、PDF、图片（PNG） | 仅 HTML |
| 导出配置 | 每种格式一套模型（`ExportConfigModels`），支持多套命名配置、页边距/纸张/缩放/是否含大纲 | 无 |
| 打印 | 打印对话框 + PDF 页面设置 | 走 WebView 的打印 |
| 导入 | 支持导入 HTML | 无 |

估计 3~5 天。Linux 上的 PDF/图片导出需要先确认 WebKitGTK 的打印能力，是这份清单里唯一有技术风险的一项。

## 差距二：图床上传

Windows 支持 OSS、Git、FTP、SCP、PowerShell 自定义脚本五种上传方式，各有配置页与多配置管理
（`UploadConfigModels`）。Uno 端没有任何一种。

每种约 0.5~1 天。用户当前的优先级是「先不做」。

## 差距三：段落菜单的图表类

Windows 的段落菜单里有 Vega 图表、流程图、时序图、PlantUML、Mermaid 五个插入项；Uno 只有一个通用的
「图表」。两端编辑器内核相同，Muya 都能渲染，只是菜单项没接。

约半天。

## 差距四：格式菜单的细项

Windows：加粗、斜体、下划线、行内代码、行内公式、删除线、高亮、超链接、图片、清除格式。
Uno：只有插入图片与清除格式，其余只能用快捷键。

约半天。

## 零碎

- 编辑菜单：Uno 缺「复制为纯文本 / Markdown / HTML」「粘贴为纯文本」「替换」（查找已有，替换未接）
- 文件菜单：Uno 缺「导入」「导出配置」
- 访问历史：Windows 存在 SQLite（`Storage.db`），Uno 存 JSON；功能等价
- 浮动 UI：Windows 用原生 XAML 浮层，Uno 由网页端绘制，风格略有差异

## 接管 Windows 的前置条件

1. **实机验证 win-x64 产物**。2026-09-24 已在 Windows 上运行过 Uno 的 exe，中文输入正常；WebView2 承载、
   多窗口、文件关联仍待验证。
2. **安装包**。Uno 端目前只产出 zip；Windows 需要 Inno 安装包、文件关联与「用 Typedown 打开」右键菜单。

最小接管集为差距一、三、四，约 4~6 天；加上图床再约 4 天。
